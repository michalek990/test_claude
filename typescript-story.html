Rozdział 01

Rok 2012.
Microsoft zmienia zasady gry.

Anders Hejlsberg — twórca C# — zamiast walczyć z JavaScript, postanowił go ulepszyć. TypeScript miał rozwiązać jeden konkretny problem: jak pisać wielki, złożony kod w języku zaprojektowanym na weekend?

Odpowiedź była elegancka: zostań nadzbiorem. Każdy poprawny JS jest poprawnym TS. Zero bariery wejścia — maksymalna nagroda.

Rozdział 02

JavaScript:
potęga i przekleństwo.

JS daje Ci wolność. Możesz przypisać cokolwiek do czegokolwiek. Number do stringa. Undefined do obiektu. Function do arraya. W małym projekcie — to wygoda. W dużym — horror.

TypeScript stawia granice. Ale to granice, które chronią, nie więzią. Jak barierki na górskiej drodze.

"TypeScript nie sprawia, że piszesz mniej kodu. Sprawia, że piszesz właściwy kod."
— Anders Hejlsberg, twórca TypeScript
JavaScript 
function add(a, b) {
  return a + b;
}

// Wynik: "23" 😱
add("2", 3);
TypeScript 
function add(
  a: number,
  b: number
): number {
  return a + b;
}
// TS łapie błąd PRZED uruchomieniem

const user = {
  name: string,
  age: number
};

// ❌ Error: Property 'email'
//    does not exist on type
console.log(user.email);

// ✅ To działa zawsze
console.log(user.name);

Supermoc po supermocy

Co dostajesz za darmo?

Każda z tych funkcji to godziny zaoszczędzonego debugowania i pewność siebie przy każdym commicie.

Statyczne typowanie
Definiujesz kształt danych raz — kompilator pilnuje reszty. Żadnych niespodzianek w runtime, żadnych cannot read property of undefined.
interfaces types enums
IntelliSense na sterydach
Autouzupełnianie które naprawdę wie, co robisz. Refaktoring bez strachu.
Generics
Piszesz funkcje raz, działają dla każdego typu. DRY na poziomie systemu typów.
Type inference
TypeScript często wie, jaki typ to jest — nawet bez Twoich adnotacji. Mniej pisania, ta sama ochrona.
Kompatybilność z ekosystemem
React, Node, Next.js, Vue, NestJS — wszystkie mają natywne wsparcie TypeScript. Nie wybierasz między TS a frameworkiem. Masz oboje.

Rozdział 03

Kto używa
TypeScript?

Nie pytaj czy używać TypeScript. Zapytaj, czy możesz sobie pozwolić na nieużywanie go. Największe firmy świata już podjęły tę decyzję.

Microsoft 100%
Google (Angular, GCP) 98%
Airbnb 95%
Slack 90%
Dropbox 88%
Kiedy TypeScript błyszczy najbardziej
Duże zespoły
Kiedy 10+ developerów pracuje nad tym samym kodem, typy są wspólnym językiem. Nikt nie musi pytać "co to zwraca?"
Długoterminowe projekty
Kod pisany 3 lata temu nadal jest zrozumiały. Refaktoring nie jest aktem wiary — jest aktem kliknięcia.
API i integracje
Typy generowane z OpenAPI, GraphQL, Prisma — Twój kod zawsze wie, jakiej formy danych oczekiwać.
Onboarding nowych devów
Nowy developer widzi typy, rozumie kontrakt, pisze poprawny kod w dzień 1. Bez legacy dokumentacji.
